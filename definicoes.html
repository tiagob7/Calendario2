Documentação

Guia rápido de cada secção de Definições
Utilizadores
Criar, editar e desativar contas de colaboradores. Atribuir escritório, role (admin/colaborador) e perfil de permissões. Admins vêem todos os utilizadores; a criação é feita do lado do cliente e fica ativa de imediato.
roles: admin · colaborador coleção: utilizadores/{uid}
Escritórios
Gerir as localizações da organização. Cada escritório tem um ID imutável (minúsculas, sem espaços), um nome, cor e ordem de apresentação. Escritórios inativos deixam de aparecer nos módulos. Guardado em config/escritorios.
IDs: lowercase, sem espaços coleção: config/escritorios
Perfis de Permissão
Define conjuntos reutilizáveis de permissões. Cada perfil configura o acesso a cada módulo (Ver / Criar / Gerir). Ao atribuir um perfil a um utilizador, as permissões são propagadas automaticamente para o documento do utilizador no Firestore.
permissões: modules.<id>.view / create / gerir coleção: config/perfis
Auditoria
Registo imutável de todas as alterações feitas na plataforma. Cada entrada contém: módulo, ação, utilizador, timestamp e diff antes/depois. As Firestore Rules proíbem update e delete — só append. Útil para rastrear quem alterou o quê.
append-only coleção: auditoria/{id}
Gerir Calendários
Publicar feriados nacionais e eventos personalizados nos calendários de cada escritório. Suporta publicação em múltiplos escritórios em simultâneo, filtros por mês/período e modo de substituição. Os dados são lidos pelo módulo Calendário de todos os colaboradores.
coleção: calendarios/{escritorioId}/{YYYY-MM}
Aparência
Personalizar o tema de cor global (Azul, Verde, Terracota, Violeta), a cor de destaque e o fundo da página. As preferências são guardadas por utilizador em Firestore e aplicadas via data-theme no elemento HTML.
campo: preferencias.dashboard.themePreset temas: default · forest · sunset · violet
Seed de Dados
Ferramenta de desenvolvimento para popular o Firestore com dados de teste. Não usar em produção. Escreve diretamente nas coleções e não pode ser desfeito. Acesso restrito a admins.
⚠ apenas em testes
Permissões seguem o padrão modules.<modulo>.<acao>. As Firestore Rules validam via map.get() dinâmico — qualquer novo módulo é suportado automaticamente sem alterar as rules.
